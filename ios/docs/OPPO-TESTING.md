# OPPO 与 iPhone / iPad 实机验证

简体中文 · [English](OPPO-TESTING.en.md)

实机操作由测试者明确安排后进行。此流程使用普通互传，不是华为分享。先用合成小文本，随后增加格式与体积；每次最多 16 文件、原始总大小 64 MiB。其他型号和所有格式不能由一个成功结果推断。

## 准备

- 两台设备打开蓝牙并连接同一 Wi-Fi；访客网络／AP 隔离可能阻断设备通信。
- iOS 允许 anDrop 的蓝牙和本地网络访问。OPPO 打开互传及可见性，必要时暂时选择所有人。
- 在发现设备及确认接收之前保持 anDrop 本体前台。iOS 26 以前，或后台任务不可用时，传输全程保持前台。

## 双向与内容

iPhone → OPPO：在本体创建测试文件或选择明确的文件，选接收设备，对方批准后核对应用完成通知、对方保存的文件名、大小和内容。

OPPO → iPhone：通过标准互传选择 anDrop，按“受信する”，检查 Received 中的结果与 SHA-256。同名重收应另存，不能覆盖已存在文件。拒绝与中止也应验证后续可重试。

随后分别验证图片、视频、PDF／Office、未知扩展名和混合批次，记录对方图标与图库结果。发送达到全部字节仍不等于完成；等待有效完成通知，并独立核对对方保存。

## 后台与共享

发送或批准接收后，在数据传输中切回主屏幕，检查系统进度、Dynamic Island／锁屏呈现和实际完成。不要把应用强制退出当作正常后台切换；它会中止传输。

共享菜单使用“选择设备 → 準備を完了 → 打开本体”开始；iPad 分屏已显示本体时按“準備済みの送信を開始”。再验证后台切换、系统停止按钮及重试。

诊断 `background_progress` 是后台实际字节，`background_transfer_finished` 记录完成时的后台状态及成功与否。带 `verification=local` 的事件来自开发用本机通信，不代表 OPPO 实机结果。

## 结果记录

记录方向、机型／OS、应用版本、文件件数／总大小、最后阶段及两端结果。原始诊断、抓包、截图与真实文件留在私有测试区域，不提交公开仓库。只公开审核后的机型／软件／结果摘要；见[验证记录](VALIDATION.md)。
