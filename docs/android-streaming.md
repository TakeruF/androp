# Android 互传：逐文件接收与有界磁盘处理

这些改动包含在 anDrop 1.3.2（13200）中，详见[更新说明](releases/1.3.2.md)。

Android 互传通过 HTTPS 接收一个 ZIP。新的接收路径边下载边解析；每个普通文件完成 ZIP CRC、实际大小、SHA-256 落盘回读、文件名及下载隔离标记检查后，即保存到用户选择的目录，无须等待整个 ZIP。已有同名文件通过数字后缀保留。中途取消或后续文件失败时，已保存文件保留，未完成的临时文件会清理。

ZIP 解析、哈希、磁盘写入及发送 ZIP 的准备放到磁盘工作线程，避免阻塞设备发现和网络控制。输入队列最多缓存两个 1 MiB 数据块。发送准备改为每次打开一个源文件、以 1 MiB 数据块复制，保持原有无压缩 STORED／ZIP64 传输格式。取消时等待工作线程结束，再清理临时目录。

接收的 ZIP 同时写入磁盘。只有最终中央目录、本地文件头、条目类型、文件数及合计大小均验证通过，才确认整个传输完成。仅中央目录中存在的属性要等目录抵达后才能验证；流式条目始终写成普通文件，不创建链接。最终元数据验证失败不会删除此前已保存的文件。

少数 ZIP 无法流式解析，例如本地文件头没有长度的 STORED 条目。这种情况会完成 ZIP 的磁盘下载，再按原有 ZIP 验证提取剩余文件，不重复保存此前已完成的文件。此兼容路径中的剩余文件仍需等待下载结束。详见上游 [stream-unzip 限制](https://stream-unzip.docs.trade.gov.uk/limitations/)。

本机检查覆盖 200 个文件、合计约 247 MiB 的内容一致性、有界 Python 内存、真实 HTTPS 下载尚未完成时的文件可见性、取消、CRC 错误、同名文件、路径拒绝、截断中央目录及兼容回退。尚未测量 Android 实机速度，也未验证 8 GB Mac 的实际体验。

华为源码的发送准备同样改为逐个打开源文件。原生持有的华为接收套接字最多预读 64 KiB，先消费已缓存的 DFile 帧再等待网络。帧格式、加密及超时规则保持。一次本机帧读取测试将 20,000 帧的读取调用从 40,000 次减少到 565 次；这不是手机实机传输速度。
