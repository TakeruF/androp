# anDrop 1.3.2

简体中文 · [English](https://github.com/TakeruF/androp/blob/main/docs/releases/1.3.2.en.md)

## 逐文件接收与大量传输

- Android ZIP 接收在格式支持流式解析时，边下载边保存已完成并验证的文件；其他 ZIP 格式先下载到磁盘，再提取剩余文件。
- 华为分享接收改用磁盘暂存，逐个保存验证完成的文件。取消或后续文件失败时，已保存文件保留，未完成文件清理；整批完成仍需通过最终协议验证。
- 移除原华为产品限制：16 个文件、发送单个 4 GiB／合计 16 GiB、接收合计 16 MiB。DFile 通信格式、可用磁盘空间及对方设备限制仍然适用，不保证任意大小的传输成功。
- 两种协议的发送准备均逐个打开源文件，以 1 MiB 分块处理。ZIP 磁盘处理移出网络事件循环，华为接收套接字采用有界预读。
- Finder 共享选择上限从 1,000 项提高到 65,535 项；各协议的传输限制仍然适用。
- 改善对方无法通过局域网连接 Mac 时的提示，说明公共 Wi-Fi 设备隔离、私人局域网及个人热点等排查方式。

## 验证与兼容性

- 开发与发行环境各通过 322 项 Python 测试，另通过 48 项 Swift 测试及 49 项同捆引擎代码测试。

- 本机测试覆盖 200 文件华为加密套接字传输、约 247 MiB 的 Android ZIP 往返、SHA-256 一致性、有界内存、提前显示已保存文件、取消、损坏归档及同名文件处理。
- 华为实机大量传输、Android 实际传输速度和 8 GB Mac 的体验尚未验证。本机套接字测试不代表实机速度或稳定性。
- 需要 Apple Silicon Mac 和 macOS 14 或以上。macOS 14 实机及 Intel 尚未验证。

## 更新与安装

在 anDrop 设置中检查更新，或下载 **anDrop-1.3.2-arm64.dmg**，替换“应用程序”中的 anDrop。保留现有设置、受信任设备和传输历史。
