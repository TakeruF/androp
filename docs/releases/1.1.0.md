# anDrop 1.1.0

简体中文 · [English](https://github.com/TakeruF/androp/blob/main/docs/releases/1.1.0.en.md)

本次更新重点改善传输稳定性，并新增失败日志与邮件反馈。

## 修复与改进

- 改善 OPPO 互联等设备互联应用运行时的连接协商：同一次传输中，对方切换网络地址或端口后可继续尝试新的有效端点，避免反复连接已失效的端口。速度测量端口被占用时，也会继续尝试传输连接。
- 修复蓝牙地址变化导致受信任设备被误拒绝的问题。现在使用成功接收时记录的协议发送者标识符，而非会变化的蓝牙 UUID。
- 修复从 Finder 共享文件时，接收设备选择窗口失去焦点、看起来立即消失的问题。
- 传输失败通知新增“查看日志”，可直接打开设置中的诊断报告；失败历史记录也可打开日志。
- 新增“诊断与问题反馈”：预览日志、在访达中显示文件，或创建发给 support@takeruf.com 的邮件草稿并附上日志。模板提供复现步骤、预期结果、接收端型号与系统版本、VPN／手机互联应用使用情况的填写栏；发送前由用户检查并确认。

## 从 1.0.0 升级

旧版信任记录不能按设备名称自动迁移。请暂时选择“所有人”，从原设备成功发送一个文件到 Mac，再将其添加为受信任设备，并移除旧记录。之后蓝牙地址变化通常无需重新添加；若对方重置协议身份，仍需重新核实。

“仅限受信任的设备”限制接收，不隐藏 Mac。未登记设备仍可能看到此 Mac，但传输请求会被拒绝；受信任设备也仍需逐次确认。这不是 AirDrop 联系人匹配或加密身份认证。

## 日志与隐私

诊断报告包含传输阶段、错误代码、文件类型与数量、设备厂商与类型、Mac／anDrop 版本及当时运行的 Mac 应用列表；不包含文件名、文件内容、设备名称、网络地址或密钥。报告保存在本机，anDrop 不会自动发送。请先检查附件，再自行发送反馈邮件。旧版失败记录可能没有详细日志。

## 安装与兼容性

- 下载 `anDrop-1.1.0-arm64.dmg`，将 anDrop 拖入 Applications 替换旧版；也可在应用中“检查更新…”。
- 支持 Apple Silicon Mac，要求 macOS 14 或更新版本；不提供 Intel 安装包。两端需开启蓝牙并连接同一局域网 Wi-Fi。
- 应用经过 Apple 公证并附带公证票据；应用和 DMG 使用 Developer ID 签名，自动更新另有签名验证。
- 已记录 OPPO 手机在 OPPO 互联连接期间的双向传输与文件内容校验，以及网络端点切换后的接收成功。其他厂商、机型及所有互联／VPN 组合尚未逐一实测，不能保证普遍兼容。
- 最低系统要求经过构建检查，macOS 14 实机与 Intel 尚未验证。此版本仍不支持 Google Quick Share、Wi-Fi Direct 或 Huawei Share。

自动化验证：99 项 Python 测试与 21 项 Swift 测试。详细范围见仓库内的测试记录与诊断文档。
