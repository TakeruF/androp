# Huawei Share 大量転送の検証記録

1.3.1（13101）のローカル検証から始めた変更を、1.3.2（13200）に含める。以下の40個／20個の方式は初期検証時の記録であり、1.3.2の送信準備は末尾のとおり1個ずつ開閉する。

従来の16ファイル、受信16 MiB、送信単体4 GiB／合計16 GiBの製品上限を送受信ともに撤廃。DFileのuint16ファイル数・ID、uint32データ連番などの通信形式、プレビューの割当枠、空き容量、OSや相手端末の制約は残る。無制限の転送成功を保証するものではない。

送信準備では最初に40個のソースファイルを開く。20個を処理するたびにその20個を閉じ、次の20個を補充する。コピー用の出力ファイルは別に最大1個。1 MiBずつ読み書きし、全内容をメモリに載せない。受信もディスクへ逐次保存し、書き込みハンドルは最大40個、上限に達した際に古い20個を閉じる。最終保存時の検証も1 MiBずつ処理する。受信データの認証、サイズ、ファイル名、安全な保存、保存後のハッシュ検証は維持する。

大量転送を妨げていた受信フレーム数の固定上限と転送全体の固定時間制限を除去し、無通信時のタイムアウトは維持。写真の付随プレビューは最大64 MiBの割当枠に拡張した（ファイル内容とは別）。

検証: 生成した200ファイル、合計約48 MiB、単体48 MiBを暗号化ソケットで往復転送し、全ファイルのSHA-256、DONE ACK、従来の受信フレーム数上限を超える転送を確認。ファイル記述子のソフト上限を256に設定した送信準備、および40個を開き20個ずつ補充する動作と失敗時のクローズも検証する。実行機は32 GBのMacであり、8 GB実機での快適性やHuawei実機200ファイル転送は未確認。

実機で確認する項目:

- Huawei → Mac、Mac → Huawei の200ファイル送受信。
- 総数、サイズ、ファイル内容の一致。0バイト、日本語名、写真・動画を含む選択。
- 転送中のメモリ使用量、応答性、キャンセル、再試行。
- 失敗時は設定から該当転送の診断ログをエクスポート。

従来の公開版1.3.1へ戻す場合は、アプリを終了して公式DMGからアプリ全体を置き換える。設定と信頼済み端末は削除しない。

## 1.3.2（13200）に含まれる変更

Huawei受信では、全ファイルの名前と合計サイズが受信許可済みの情報と一致することを確認した後、1ファイルの受信・認証・サイズ／ハッシュ検証が完了するたびに、そのファイルを保存先へ移す。未完了のファイルは引き続き非表示の一時領域に置く。既存ファイルと同名の場合は別名で保存する。

途中でキャンセルや通信エラーになっても、既に検証して保存先へ移したファイルは残す。転送全体を「完了」とするのは、従来どおり全件と最後のDONE ACKを確認してから。当初はコード変更のみにとどめ、その後ユーザーの更新指示により1.3.2へ適用した。

1.3.2の送信準備は、ユーザー指定により40個／20個の入れ替えから「1個ずつ開閉」に変更。Huaweiの受信ソケットは最大64 KiBを先読みし、既存バッファ内のDFileフレームを通信待ちせず処理する。1.3.2で適用済みだが、実機の速度改善は未確認。Android側の同様の変更は [説明](android-streaming.en.md) を参照。
